Zigbee2MQTT, but sensible.

A Zigbee to MQTT bridge you never have to understand Zigbee to use. Every device Zigbee2MQTT supports, a live map that shows what's wrong and why, errors in plain English, and no YAML.

Install

On a Debian-based Linux machine (Debian, Ubuntu, a Proxmox container), run this. It installs Node.js if needed, sets Swarm2MQTT up as a service and starts it.

curl -fsSL https://raw.githubusercontent.com/hazymat/swarm2mqtt/main/scripts/install.sh | sudo bash -s -- --dev

Then open http://your-machine:8080 and the setup takes you through the rest, including bringing your network over from Zigbee2MQTT without re-pairing anything.

See what's wrong, and why

Zigbee problems are usually about signal and routes. Swarm2MQTT shows you both.

A map that stays true

  • Who talks through whom, with every link coloured good, fair or weak.
  • Learns routes from normal traffic on Silicon Labs (Ember) adapters: when a device moves to another plug, the map changes at once.
  • Signal in dBm, from each device's own messages, and per hop: when a sensor is slow because the plug it talks through has a weak link, it says so.
  • Offline means offline. It learns how often each device checks in, so a quiet motion sensor isn't flagged as gone.

Adding devices that actually join

  • One button. Joining turns itself off after 4 minutes, and you're told why that matters.
  • Join near a plug for a device you can't move, like a radiator valve: only that plug lets it in.
  • Half-joined devices are explained in plain words, and fixed with Remove and add again.
  • New devices wait for you before anything is published over MQTT.

MQTT you can see

  • How it's sent: topic, one message or one topic per value, renamed values, and how often it reports, per device.
  • Sent over MQTT: the last messages for each device, with what changed, open to look inside.
  • Only confirmed values go out. A change shows as done only when the device confirms it.
  • Same topics and message shapes as Zigbee2MQTT, so Node-RED and Home Assistant don't notice the switch.

Sensible by default

The things that make Zigbee2MQTT hard work, handled for you.

No YAML, ever

Everything is set up in the browser. A setup wizard gets your network running, then settings live in plain panels.

Switch without re-pairing

It brings your network, devices, names and groups over from Zigbee2MQTT, checks it took the right network, and keeps your MQTT topic.

Never wipes your network

If its settings don't match what the adapter holds, it stops and tells you, rather than erasing the adapter's network.

Undo everything

Every change can be undone, removing a device included. Undo history says what changed, where, and what it was before.

Errors in plain English

"The adapter didn't answer" comes with what to try, not a stack trace. Activity logs what happened, system and devices alike.

Every device Zigbee2MQTT supports

Built on the same device library, so support for new devices arrives with each of its releases.

What you need

A Zigbee adapter

Silicon Labs (Ember, e.g. SLZB-06M, Sonoff ZBDongle-E) or Texas Instruments (Z-Stack) based, on the network or USB.

An MQTT broker

Mosquitto or any other. Swarm2MQTT finds Zigbee2MQTT on it if you're moving over.

A small Linux machine

Debian-based, always on. A Proxmox container with 512 MB of memory is plenty.

About the developer

Hello, I’m Mat, from London. I wrote Swarm2MQTT primarily for my own home, but I hope you like it too.

Computer Science was my first degree and I’ve been coding since 1988. But you may have guessed AI tools were involved somewhat in the production of Swarm2MQTT’s code. Please don’t let that put you off. I’m a critical and careful user of AI, and value human decisions far more than computer-made ones. And so my approach is this: human-led design and human-checked code.

Swarm2MQTT stands on the shoulders of zigbee-herdsman and zigbee-herdsman-converters, by Koen Kanters and the Zigbee2MQTT community, which do the talking to Zigbee devices. Thank you to everyone who works on them.

If something is wrong, or could be improved, please let me know in GitHub Discussions.
